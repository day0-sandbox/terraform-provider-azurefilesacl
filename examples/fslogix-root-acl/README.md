# FSLogix Root ACL Local Test

This example validates and applies FSLogix root ACLs against an existing Azure Files share.

Run the local validation:

```bash
./test-local.sh validate
```

Run a local plan:

```bash
./test-local.sh plan
```

The helper builds the provider into `/tmp/azurefilesacl-dev` and sets `TF_CLI_CONFIG_FILE` to this example's real `dev.tfrc` path.

Manual equivalent:

```bash
mkdir -p /tmp/azurefilesacl-dev
GOTOOLCHAIN=auto go -C ../.. build -o /tmp/azurefilesacl-dev/terraform-provider-azurefilesacl .

TF_CLI_CONFIG_FILE="$(pwd)/dev.tfrc" terraform -chdir=. validate
```

Apply missing managed ACEs while preserving existing ACL entries:

```bash
./test-local.sh apply
```

For this local example, `apply` can use either:

- `auth_method=oauth` with `storage_account_resource_id` so the provider can fall back to ARM `listKeys`, or
- `auth_method=account_key` for explicit local validation.

Run the additive write path explicitly:

```bash
./test-local.sh apply-account-key -auto-approve -var='acl_mode=additive'
```

Run the validate path with an account key:

```bash
./test-local.sh apply-account-key -auto-approve -var='acl_mode=validate'
```

Run destroy with full managed-ACE removal:

```bash
./test-local.sh destroy
```

Destroy removes the exact ACEs generated by this resource from the Azure Files DACL, then removes Terraform state. Unknown ACEs, owner, group, SACL, and DACL flags are preserved.

The resource defaults to `mode = "additive"`, so apply adds missing managed ACEs without overwriting existing ACL entries. Use `acl_mode = "validate"` when you want a read-only check that fails if configured ACEs are missing.

This example uses Microsoft Graph resolution for hybrid users and a hybrid group. The users are supplied by UPN, the group is supplied by object ID, and `identity_mode` must match the Azure Files identity setup. Hybrid modes use `onPremisesSecurityIdentifier`; cloud-only modes use `securityIdentifier`.
